1. KEM KIM 분석 과정

1. 데이터 로딩

분석의 첫 단계로, CSV 파일에서 텍스트 데이터를 불러옵니다. 이 데이터는 데이터의 텍스트와 각 문서의 날짜 정보로 구성됩니다.

2. 데이터 전처리

불러온 데이터를 분석에 적합한 형태로 변환하고, 그룹화하는 과정입니다. 이 단계에서는 다음과 같은 작업이 이루어집니다:

  • 날짜 변환: 데이터의 날짜 정보를 표준화된 형식(예: YYYY-MM-DD)으로 변환합니다.
  • 기간 그룹화: 데이터를 사용자가 지정한 기간(예: 월, 분기, 연도)으로 그룹화합니다. 예를 들어, 연도별로 데이터를 그룹화하면, 각 연도별로 키워드 분석을 수행할 수 있습니다.

3. 키워드 추출

텍스트 데이터에서 빈도가 높은 단어들을 추출하여 키워드로 지정합니다. 이 과정에서 다음 작업이 포함됩니다:

  • 빈도 계산: 각 기간마다 텍스트 데이터에서 자주 등장하는 단어들의 빈도를 계산합니다.
    • 단어 빈도(기간) = 해당 기간에 등장한 특정 단어의 총 횟수
  • 공통 키워드 추출: 모든 기간에 걸쳐 공통으로 등장하는 상위 빈도 단어들을 분석 대상으로 선택합니다. 상위 단어 개수는 KEM KIM 실행 시 "상위 단어 개수"로 조정할 수 있습니다

4. 분석

각 기간별로 키워드의 중요성을 분석합니다. 주요 분석 단계는 다음과 같습니다:

  • TF 계산: 각 기간마다 키워드의 등장 횟수를 계산합니다. 이 값은 TF (Term Frequency)로 정의되며, 특정 기간에 해당 단어가 얼마나 자주 등장했는지를 나타냅니다.
  • DF 계산: 키워드가 등장한 문서의 수를 계산하여 DF (Document Frequency)로 정의합니다. 이 값은 해당 기간 동안 얼마나 많은 문서에서 해당 키워드가 언급되었는지를 보여줍니다.
  • DoV 계산: 각 기간마다 키워드의 시인성을 계산합니다. 실제 구현은 기간 안의 전체 문서 수로 나눈 TF에 시간 가중치를 곱합니다. DoV (Degree of Visibility)로 정의되며, 특정 기간에 해당 단어의 시인성을 나타냅니다. 수식은 다음과 같습니다
    • DoV(t) = TF(t) / 문서 수(t) × [1 − weight × n(t)]
  • DoD 계산: 기간 안에서 해당 단어가 등장한 문서 수(DF)를 기간의 전체 문서 수로 나눈 뒤 같은 시간 가중치를 곱합니다. DoD (Degree of Diffusion)는 문서 전체로 퍼진 정도를 나타냅니다.
    • DoD(t) = DF(t) / 문서 수(t) × [1 − weight × n(t)]
  • 증가율 계산: 최종 지도에서는 첫 분석 기간과 마지막 분석 기간의 DoV·DoD를 비교합니다. ((마지막 값 / 첫 값)^(1 / 기간 간격 수) − 1) × 100으로 계산하는 기간당 복합 증가율입니다. 양 끝 값 중 하나가 0 이하이면 증가율을 0으로 둡니다. 주·월·분기 분석에서도 축 이름은 증가율(%)이며, 연율로 환산하지 않습니다.

5. 시각화 및 데이터 저장

분석된 데이터를 그래프로 시각화하고, 결과를 다양한 형식으로 저장합니다. 주요 단계는 다음과 같습니다:

  • 그래프 생성:그래프는 KEM과 KIM 두 가지 형태로 생성됩니다:
    • KEM (Keyword Emergence Map): X축은 첫·마지막 기간 TF의 평균, Y축은 같은 두 기간 DoV의 기간당 복합 증가율입니다.
    • KIM (Keyword Issue Map): X축은 첫·마지막 기간 DF의 평균, Y축은 같은 두 기간 DoD의 기간당 복합 증가율입니다.
  • Signal 분석:KEM, KIM 그래프 내부의 사분면을 기준으로 키워드의 중요도에 따라 네 가지 유형으로 분류합니다:
    • 강한 신호(Strong Signal): 높은 단어 빈도와 높은 증가율을 가진 키워드입니다.
    • 약한 신호(Weak Signal): 낮은 단어 빈도와 높은 증가율을 가진 키워드입니다.
    • 잠재 신호(Latent Signal): 낮은 단어 빈도와 낮은 증가율을 가진 키워드입니다.
    • 잘 알려진 신호(Well-Known Signal): 높은 단어 빈도와 낮은 증가율을 가진 키워드입니다.
  • 결과 저장: 단어 빈도, 문서 빈도, DoV, DoD 등 분석 결과를 CSV 파일로 저장합니다. 또한, 분석 결과를 시각화한 그래프를 PNG 파일로 저장합니다.



2. MANAGER KEM KIM 연산 절차

1. 추적 데이터 생성

비일관 단어 필터링을 켠 경우 전체 분석 기간의 각 구간을 끝점으로 삼아 추적 지도를 계산합니다. 추적 기준이 시작연도이면 첫 구간부터 현재 구간까지, 직전연도이면 바로 앞 구간과 현재 구간을 비교합니다. 예를 들어 연 단위 데이터라면 각 연도를 끝점으로 한 추적 결과를 만들며, 기간마다 후보 단어의 신호 위치를 기록합니다:

  • DoV/DoD, Signal 추적: 각 기간 동안 키워드의 DoV 및 DoD, Signal을 추적하여 키워드가 시간에 따라 어떻게 변화했는지를 분석합니다.
  • 신호 변화 기록: 각 키워드의 Signal 변화를 기록하고, 이 데이터를 CSV 파일, 그래프, 애니메이션으로 저장합니다

2. 시그널 필터링 및 좌표 데이터 업데이트

추적된 데이터에서 시계 방향으로 Signal 이동이 일어나지 않은 키워드를 걸러내고, 해당 키워드 제외 사전에 추가합니다:

  • 시그널 필터링: 각각의 키워드에 대해서, Period별 Signal 변화를 추적하고, Signal 이동이 시계 방향으로 진행되지 않은 경우, 해당 키워드를 필터링합니다.
  • 최종 지도 반영: 추적 결과가 시계방향 이동 규칙을 통과하지 못한 단어는 제외 목록에 추가됩니다. 최종 지도는 첫 기간과 마지막 기간의 지표로 계산하며, 사용자 제외 단어와 자동 제외 단어는 최종 좌표와 신호 분류에서 제외됩니다. 이 필터는 후보 키워드 자체나 기간별 Data CSV를 지우지 않습니다.
  • 최종 좌표 데이터 저장: 필터링된 좌표 데이터를 CSV 파일로 저장하여, 최종 분석 결과에 반영됩니다.

3. 최종 결과물 생성 및 저장

최종적으로 필터링된 데이터를 기반으로 KEM KIM 분석 결과를 생성하고, 결과를 저장합니다:

1. 최상위 폴더: kemkim_folder_path

최종 분석 결과가 저장되는 최상위 폴더로, 폴더명은 분석 대상 CSV 파일 이름과 분석 기간, 분석 시간에 기반하여 생성됩니다.

2. Data 폴더

주기별로 계산된 TF, DF, DoV, DoD 데이터를 저장합니다.

  • TF/YYYY_TF.csv: 각 기간에 대해 키워드의 단어 빈도(Term Frequency) 데이터가 저장됩니다.
  • DF/YYYY_DF.csv: 각 기간에 대해 키워드의 문서 빈도(Document Frequency) 데이터가 저장됩니다.
  • DoV/YYYY_DoV.csv: 각 기간에 대해 키워드의 DoV(Time-Weighted 증가율) 데이터가 저장됩니다.
  • DoD/YYYY_DoD.csv: 각 기간에 대해 키워드의 DoD(Time-Weighted 증가율) 데이터가 저장됩니다.

3. Result 폴더

최종 분석 결과와 시각화 자료를 저장합니다.

  • Graph: 최종 분석 결과를 바탕으로 생성된 그래프 이미지 파일이 저장됩니다.
  • Signal: 최종 Signal 분석 결과가 CSV 파일로 저장됩니다.

4. Trace 폴더

추적 분석을 위한 중간 결과와 최종 결과를 저장합니다.

  • Trace_Result: 각 기간별로 Signal 분석 결과와 그래프 이미지 파일이 저장됩니다.
  • Trace_Data: 추적 분석을 위해 사용된 DoV 및 DoD 데이터가 저장됩니다.
    • DoV: 각 기간별로 키워드의 DoV 데이터가 저장됩니다.
    • DoD: 각 기간별로 키워드의 DoD 데이터가 저장됩니다.

2-1. 실제 계산 방식과 분석 설정

토큰 CSV를 올리거나 크롤링 DB에서 토큰 파일을 고른 뒤 분석 기간과 옵션을 정합니다. 일반 실행의 기본값과 효과는 다음과 같습니다.

설정기본값의미
분석 시작일·종료일파일명에서 날짜를 읽을 수 있으면 자동 제안선택 범위 밖의 문서는 제외됩니다.
분석 기간 단위1년1년, 반기, 분기, 1개월, 1주, 1일 중 선택합니다.
시간 가중치0.1기간 간격마다 과거 DoV·DoD에 적용할 감쇠 계수입니다. 분석 구간 수가 많을 때 (구간 수−1) × weight가 1 이상이면 오류로 종료됩니다.
상위 단어 개수500각 기간에서 공통 후보를 찾을 때 사용할 상위 목록의 크기입니다.
표시 단어 개수10애니메이션 그래프에 기간별 상위 단어를 몇 개 표시할지 정합니다.
분할 기준평균(Mean)각 지도에서 신호 사분면을 나눌 X·Y 경계를 선택합니다. 평균, 중앙값, 또는 상위 백분위 직접 입력을 쓸 수 있습니다.
추적 계산 기준시작 기간필터링용 추적 지도에서 첫 기간부터 누적 비교할지, 직전 기간과 비교할지 선택합니다.
비일관 단어 필터링켜짐기간별 이동 경로를 계산하고 규칙에 맞지 않는 단어를 최종 지도에서 제외합니다.
애니메이션 생성꺼짐켜면 기간별 TF·DF·TF-IDF·DoV·DoD 및 신호 이동 GIF를 추가 생성합니다.

분석 입력은 형태소 분석을 새로 수행하는 원문이 아니라, 각 문서의 토큰을 쉼표와 공백(, )으로 이어 붙인 토큰 CSV입니다. 날짜 열 이름에 Date, 본문 열 이름에 Text가 들어 있어야 합니다. 날짜는 YYYY-MM-DD 형식을 읽고, 선택한 시작일과 종료일에 포함되는 행만 분석합니다. 날짜가 읽히지 않는 행은 기간에 들어가지 않습니다.

  1. 기간으로 묶기: 일(1d), 주(1w), 월(1m), 분기(3m), 반기(6m), 연(1y) 단위로 묶습니다. 분석 구간이 2개 미만이면 실행할 수 없습니다.
  2. 공통 키워드 정하기: 각 기간에서 토큰 출현 횟수 상위 N개를 먼저 고른 뒤, 모든 기간의 상위 목록에 공통으로 포함된 단어만 최종 후보로 씁니다. 따라서 한 기간에서만 많이 나온 단어는 상위 N개에 들더라도 후보에서 빠질 수 있습니다. 후보 단어는 길이 2자 이상이어야 합니다.
  3. TF와 DF: TF는 기간의 토큰 전체에서 단어가 나온 횟수이고, DF는 그 단어가 한 번 이상 포함된 문서 수입니다. 한 문서에서 여러 번 나와도 DF에는 1건으로 셉니다. 참고용 TF-IDF 파일은 TF × ln(기간 문서 수 / DF)로 계산됩니다.
  4. 시간 가중치: n(t)은 기준 기간과 해당 기간 사이의 구간 수입니다. 최종 지도는 마지막 기간을 기준으로 하므로 오래된 기간일수록 더 큰 n이 적용됩니다. 추적 분석에서 기준을 시작연도로 고르면 첫 기간부터의 거리, 직전연도를 고르면 매번 직전 기간을 기준으로 계산합니다. 가중치가 커질수록 과거 DoV·DoD가 더 많이 낮아집니다.
  5. 신호 분류 경계: KEM과 KIM은 각각 단어별 좌표를 만든 뒤 설정한 분할 기준으로 X·Y 경계선을 정합니다. 기본은 각 축의 평균(Mean), 선택 가능한 대안은 중앙값(Median) 또는 상위 백분위 직접 입력입니다. 경계선 기준으로 강한·약한·잠재·알려진 신호를 나눕니다. 최종 신호 CSV에는 DoV 기반 KEM과 DoD 기반 KIM에서 같은 유형으로 분류된 단어가 함께 기록됩니다.

분석 설정의 의미: 상위 단어 개수는 기간별 후보 폭을, 시간 가중치는 과거 신호의 감쇠 정도를 조정합니다. 비일관 단어 필터링은 기간별 신호 사분면 이동이 설정된 시계방향 규칙을 따르지 않는 단어를 최종 지도에서 제외합니다. 추적 기준은 이 필터링의 기간별 계산에도 영향을 줍니다. 제외 단어는 사용자가 지정한 단어와 자동 필터링된 단어 모두 filtered_words.csv에서 확인할 수 있습니다.

2-2. 결과 파일과 프로젝트 사용

분석이 끝나면 결과 디렉터리를 ZIP으로 내려받고, 로그인 상태에서는 같은 결과를 온라인 뷰어 프로젝트로도 저장합니다. 프로젝트는 사용자별로 보관되며 뷰어에서 이름 변경, 폴더 이동, 삭제, 결과 ZIP 재다운로드를 할 수 있습니다. 분석 진행 화면을 닫아도 서버 작업은 계속되지만, 서버가 재시작되면 진행 중 작업의 상태 조회는 중단될 수 있습니다.

3. 해석 기능과 AI 신호 해석

KEM KIM 그래프는 어떤 단어가 신호인지 알려 주지만 왜 신호가 되었는지는 알려 주지 않습니다. 뷰어의 해석 섹션은 토큰화 전 원본 기사로 돌아가 단어가 실제로 어떤 맥락에서 쓰였는지 찾아 줍니다. 해석 기능은 세 가지입니다.

기능질문AI 사용
키워드 문맥 해석고른 단어들이 들어간 기사와 그 앞뒤 문장은?선택(제목 기반 주제 요약)
AI 신호 해석 (단어별)이 단어는 약한 신호일 때 어떤 맥락이었고, 신호가 커지며 어떤 맥락으로 옮겨 갔나?사용
신호군 종합 해석약한 신호(또는 다른 신호군) 단어들은 어떤 떠오르는 이슈로 묶이나?사용

3-1. 원본(토큰화 전) CSV 준비

해석은 KEM KIM 분석에 쓴 토큰 CSV와 같은 데이터의 원본이 필요합니다. 원본은 Date와 Text 열이 반드시 있어야 하고, Title 열이 있으면 기사 제목도 함께 보여 줍니다(열 이름에 해당 단어가 들어 있으면 인식합니다). 한 번 첨부하면 프로젝트에 저장되어 다시 첨부할 필요가 없고, 새로 첨부하면 교체됩니다. 첨부된 원본의 출처는 해석 섹션에 표시됩니다.

원본을 첨부하는 방법은 세 가지입니다.

  • 분석에 쓴 DB의 원본 불러오기 — 새 프로젝트를 크롤링 DB에서 선택해 분석했다면, 뷰어가 어느 DB의 어떤 토큰 파일로 분석했는지 기억합니다. 해석 섹션에 나타나는 이 버튼을 누르면 같은 DB에서 짝이 맞는 원본 파일(토큰 파일 이름에서 token_을 뺀 파일)을 바로 첨부합니다. 이 기능 도입 이후 크롤링 DB로 분석한 프로젝트에서만 나타납니다.
  • 크롤링 DB에서 원본 선택 — 크롤링 DB 목록에서 DB를 고르면 토큰화되지 않은 원본 파일만 보여 주고, 누르면 첨부합니다. 완료된 크롤링만 목록에 나옵니다.
  • 파일 직접 업로드 — 가지고 있는 원본 CSV를 올립니다.

3-2. 키워드 문맥 해석

해석할 키워드를 여러 개 고르고 OR(하나라도 포함) 또는 AND(모두 포함)로 기사를 찾습니다. 분석 기간(시작일~종료일) 안의 기사만 대상이며, 기사마다 키워드 앞뒤 200자를 문맥으로 보여 줍니다. AI로 주제 요약을 켜면 찾은 기사 제목 중 앞 50개를 AI에게 보내 공통 주제 1~5개를 요약하게 합니다. 결과는 CSV로 내보낼 수 있습니다.

3-3. AI 신호 해석 (단어별)

실행 방법: 그래프에서 단어를 눌러 오른쪽 단어 정보의 ✦ AI 신호 해석 버튼을 누르거나, 해석 섹션의 AI 신호 해석 칸에 단어를 입력하고 단어 해석을 누릅니다. 그래프에 있는 단어만 해석할 수 있습니다. 원본 CSV가 없으면 아래 ①~④의 수치 분석까지만 보여 주고 AI 해석은 건너뜁니다.

AI 신호 해석은 숫자로 판정하는 부분(①~④)과 원본에서 근거를 뽑는 부분(⑤~⑦), AI가 서술하는 부분(⑧~⑨)으로 나뉩니다. 신호 단계는 AI가 정하지 않습니다.

① 기간별 신호 단계 판정

KEM KIM 결과의 Data 폴더에 있는 기간별 DoV·DoD 값으로, 기간마다 그 단어가 네 신호 중 어디에 있었는지 판정합니다. KEM 단계는 DoV, KIM 단계는 DoD로 같은 방식으로 계산합니다.

  • 값 x(t) = 기간 t에서 단어의 DoV(또는 DoD)
  • 증가율 g(t) = (x(t) ÷ x(t−1) − 1) × 100 — 직전 기간에 없던 단어는 신규로 보고 증가율이 높은 쪽으로 판정합니다.
  • 같은 기간에 값이 있는 모든 단어의 x 중앙값과 모든 단어의 증가율 중앙값을 기준선으로 삼아 사분면을 나눕니다.
    • x ≥ 중앙값, g ≥ 중앙값 → 강한 신호
    • x < 중앙값, g ≥ 중앙값 → 약한 신호
    • x < 중앙값, g < 중앙값 → 잠재 신호
    • x ≥ 중앙값, g < 중앙값 → 알려진 신호
  • 첫 기간은 증가율을 알 수 없으므로 x만 보고, 중앙값 이상이면 알려진 신호, 미만이면 잠재 신호로 둡니다.
  • 그 기간에 값이 없거나 0이면 미등장입니다.

최종 판정과의 차이: 그래프의 최종 신호(단어 옆 최종·KEM·KIM 배지)는 KEM KIM 분석이 첫 기간과 마지막 기간 사이의 시간 가중 연평균 증가율로 정한 값이고, 여기의 기간별 단계는 그 사이 흐름을 보여 주기 위한 참고 판정입니다. 두 값이 다를 수 있습니다.

② 한 기간짜리 출렁임 보정

짧은 기간 단위에서는 증가율이 크게 출렁여 단계가 해마다 바뀌기 쉽습니다. 앞뒤 기간의 원래 판정이 같은데 가운데 한 기간만 다르면, 가운데를 앞뒤 단계로 맞춥니다. 판정을 바꾼 기간도 원래 판정은 결과 데이터에 함께 저장됩니다.

③ 집계가 끝나지 않은 마지막 기간

분석 종료일이 마지막 기간의 끝보다 이르면(예: 연 단위 분석인데 4월 30일에 끝남) 그 기간은 기사가 덜 모여 값이 줄어든 것처럼 보입니다. 이런 기간은 직전 단계를 이어받고 단계 옆에 *, 그래프에는 속이 빈 점으로 표시합니다. 실제 감소로 읽지 마세요.

④ 국면 나누기

같은 단계가 이어지는 기간을 하나의 국면으로 묶습니다(미등장 기간은 제외). 국면이 5개를 넘으면 가장 짧은 국면을 이웃 국면 중 더 긴 쪽에 합쳐 5개 이하로 만듭니다. 그래프의 색띠와 국면별 맥락 카드가 이 국면입니다.

⑤ 원본 기사를 기간에 맞추기

원본의 Date를 KEM KIM이 쓴 기간 이름과 같은 규칙으로 바꿔 기사마다 기간을 붙입니다. 연(2021), 월(2021-03), 분기(2021Q1), 반기(2021H1), 주(20210301-20210307), 일(2021-03-01) 단위를 모두 지원하며, 분석 기간 밖의 기사는 제외합니다. 그다음 본문(Text)에 단어가 들어 있는 기사를 모읍니다.

⑥ 국면별 연관어

관련 기사에서 단어를 뽑아(한글 2글자 이상, 영문 3글자 이상) 국면마다 그 국면에서 유독 많이 나온 말을 고릅니다.

  • 점수 = 국면 안에서 그 말이 나온 기사 수 × 향상도
  • 향상도 = (국면 안 비율) ÷ (전체 관련 기사 안 비율) — 모든 국면에 고르게 나오는 말은 낮아지고 그 국면에만 몰린 말은 높아집니다.
  • 다음 말은 뺍니다: 분석 단어 자신과 그 활용형(예: 검거 → 검거율), ~다·~니다·~요로 끝나는 서술어, 기사 상투어(기자, 무단 전재 등), 관련 기사의 80% 이상에 나오는 배경어(보통 크롤링 검색어), 국면 기사가 5건 이상일 때 1건에만 나온 말.
  • 흔한 조사(은/는/을/를/의/에서 등)는 떼어 같은 말로 셉니다. 단 이·가는 명사의 일부인 경우가 많아(오토바이, 아이) 세 글자 어형에서만 뗍니다.

기간별 연관어 자세히 보기 표는 같은 방식으로 기간마다 계산하며, 이전 기간 상위 연관어에 없던 말을 새(파란색)로 표시합니다.

⑦ 대표 문맥(근거)

국면마다 연관어를 많이 담은 기사부터 제목이 겹치지 않게 골라, 단어 앞뒤 160자를 문맥으로 잘라 둡니다. 국면당 최대 6개, 전체 최대 36개이며 각 문맥에는 S1, S2 … 번호가 붙습니다. 이 번호가 AI 해석의 근거 인용에 쓰입니다.

⑧ AI 해석

AI에게는 다음을 보냅니다. 어떤 모델에 보낼지는 사용자의 AI 모델 설정을 따릅니다. 실제로 보낸 내용은 결과 화면의 AI에게 보낸 프롬프트 보기를 펼쳐 확인할 수 있습니다(기본은 닫힘). 해석이 진행되는 동안에도 프롬프트가 만들어지는 즉시 펼쳐 볼 수 있습니다.

  • 시스템 지시: KEM KIM 네 신호의 뜻, 주어진 국면·연관어·문맥만 근거로 쓸 것, 모든 주장에 문맥 번호를 달 것, 연관어는 주어진 목록에서만 고를 것, 문맥에 없는 사건·수치·기관을 지어내지 말 것, 그리고 답변 형식(JSON).
  • 입력 데이터: 분석 단어, 분석 자료 이름·기간·기간 단위, 최종 판정(최종/KEM/KIM), 처음 등장한 날과 관련 기사 수, 기간별 수치 표(기사 수·TF·DoV·증가율·단계), 국면별로 기간 범위·단계·기사 수·연관어·대표 문맥(번호, 날짜, 제목, 본문 일부).
  • AI가 돌려주는 것: 한 줄 요약, 종합 해석, 국면마다의 맥락 서술·대표 연관어·근거 번호, 맥락 이동(예: 절도 → 연령 하향 논쟁 → 디지털 성범죄), 신호를 키운 계기, 앞으로 주목할 점, 함께 볼 연관어, 해석의 한계.
  • AI 응답이 형식에 맞지 않으면 같은 모델에 한 번 더 형식에 맞춰 달라고 요청합니다. 그래도 안 되거나 모델이 응답하지 못하면 AI 모델 설정에 따라 다음 모델(예: 내 GPT API)로 넘어갑니다.
  • 추론형 모델(gpt-oss 등)은 답을 쓰기 전에 생각하는 데 출력 한도를 쓰기 때문에 넉넉한 한도(단어별 8,000토큰, 신호군 6,000토큰)를 주고, 그래도 생각만 하다 한도를 넘기면 한도를 두 배로 늘려 한 번 더 요청합니다.
  • 결과 화면 아래에 실제로 답한 모델(예: 로컬 LLM, gpt-5-mini (내 API 키))과, 내 API 키를 썼다면 추정 비용, 앞선 모델이 실패한 이유가 표시됩니다.

⑨ AI 답변 검증

AI 답변은 화면에 보여 주기 전에 서버에서 한 번 거릅니다.

  • 근거 번호는 실제로 보낸 문맥 번호만 남기고, 없는 번호는 지웁니다.
  • 대표 연관어와 함께 볼 연관어는 실제로 뽑은 연관어 목록에 있는 말만 남깁니다.
  • 국면은 ④에서 정한 국면 번호대로만 표시합니다.

화면의 근거는 AI가 쓴 문장이 아니라, 그 번호에 해당하는 실제 기사 문맥을 그대로 보여 줍니다. 연관어를 누르면 그 단어의 신호 해석으로 이어집니다.

⑩ 실행 방식과 저장

  • AI 해석은 1~2분 걸릴 수 있어 서버에서 백그라운드 작업으로 돌고, 화면은 2초마다 진행 단계(맥락 추출 중, AI 해석 중 등)를 확인합니다. 창을 닫아도 작업은 계속되며 끝나면 해석 목록에 저장됩니다. 단, 작업 도중 서버가 다시 시작되면 진행 중이던 작업은 사라집니다.
  • 결과는 해석 목록에 📈 표시로 저장되며, 수치·국면·근거·프롬프트를 담은 보고서(.md)로 내보낼 수 있습니다.

3-4. 신호군 종합 해석

해석 섹션에서 기준(최종/KEM/KIM)과 신호(약한·강한·잠재·알려진)를 고르고 신호군 종합 해석을 누릅니다. 원본 CSV가 필요합니다.

  • 그 신호군의 단어를 최대 40개까지 씁니다.
  • 단어마다 관련 기사 수, 처음 등장한 기간(DoV 값이 처음 생긴 기간), 정점 기간(DoV가 가장 큰 기간), 자주 함께 나온 말 6개(관련 기사 최대 400건 기준), 가장 최근 기사의 문맥 1개(번호 포함)를 모아 AI에게 보냅니다.
  • AI는 단어들을 떠오르는 이슈 2~6개로 묶고, 가장 주목할 단어를 최대 3개 고릅니다.
  • 원본 기사에 한 번도 나오지 않는 단어는 AI가 근거 없이 추측하게 되므로 AI 입력에서 빼고 원본 기사에서 찾지 못한 단어로 따로 보여 줍니다. 모든 단어가 원본에 없으면 원본 CSV가 분석 데이터와 같은지 확인하라는 안내와 함께 멈춥니다.
  • 검증: 신호군에 없는 단어는 지우고, 한 단어는 한 이슈에만 들어가게 하며, 근거 번호는 실제로 보낸 번호만 남깁니다. 어느 이슈에도 묶이지 않은 단어는 따로 보여 줍니다.
  • 결과는 해석 목록에 🧭 표시로 저장되고 보고서로 내보낼 수 있습니다. 프롬프트도 같은 방식으로 펼쳐 볼 수 있습니다.

3-5. 결과를 읽을 때 주의할 점

원본과 토큰 파일이 같은 데이터여야 합니다. 다른 크롤링의 원본을 첨부하면 수치(①~④)와 맥락(⑤~⑦)이 서로 다른 데이터에서 나와 해석이 어긋납니다.

기사 찾기는 글자 포함 검색입니다. 분석 단어가 들어간 다른 말(예: '검거'가 '검거율'에도)과 동음이의어도 함께 잡힙니다. 근거 문맥을 직접 확인하세요.

기간별 단계는 참고 판정입니다. 같은 기간 다른 단어들과의 상대 비교이므로, 전체 기사 수가 크게 변한 기간에는 단계가 크게 흔들릴 수 있습니다.

AI 서술은 가설입니다. 주어진 문맥 밖의 추측은 하지 않도록 지시하고 결과도 검증하지만, AI가 문맥을 잘못 읽을 수는 있습니다. 보고서나 발표에 쓸 때는 근거 문맥과 원문을 함께 확인하세요.

3-6. AI 모델 설정 (로컬 LLM / 내 GPT API)

AI 해석(단어별 신호 해석, 신호군 종합 해석, 키워드 해석의 AI 주제 요약)에 쓸 모델은 사용자마다 고를 수 있습니다. 상단 네비게이션 바의 ⚙ 설정 버튼을 누르면 테마 아래에 AI 모델 영역이 있습니다. 한 번 저장하면 로그인한 계정 기준으로 모든 KNPU 사이트에 똑같이 적용됩니다.

사용 방식동작비용
로컬 LLM만 사용 (기본)연구실 서버의 LLM(gpt-oss 등)만 씁니다. 서버에 공용 예비 모델이 설정돼 있으면 로컬이 실패할 때 그쪽을 씁니다.없음
로컬 LLM 우선, 실패하면 내 GPT API먼저 로컬 LLM에 요청하고, 연결 실패·빈 응답·형식 오류로 해석하지 못하면 내 OpenAI API 키로 다시 요청합니다.로컬이 실패했을 때만
항상 내 GPT API처음부터 내 OpenAI API 키로 요청합니다. 해석 품질이 가장 안정적입니다.매 요청
  • API 키: OpenAI에서 발급한 sk-로 시작하는 키를 입력합니다. 저장할 때 OpenAI에 실제로 확인해 잘못된 키는 받지 않습니다. 키는 서버에 암호화해 보관하고, 화면에는 끝 4자리만 보입니다. 키 삭제로 언제든 지울 수 있습니다.
  • 모델: gpt-5-mini(기본), gpt-5-nano, gpt-5, gpt-4.1-mini 중에서 고릅니다. 옆의 숫자는 100만 토큰당 입력/출력 요금(USD)입니다.
  • 월 사용 한도(USD): 이번 달 내 API 키로 쓸 수 있는 최대 금액입니다. 요청하기 전에 예상 비용(프롬프트 길이와 출력 한도로 계산)이 남은 한도를 넘으면 내 API를 쓰지 않고, 그 이유를 결과 화면에 알려 줍니다. 한도는 매월 1일(UTC 기준)에 새로 시작합니다.
  • 사용량: 이번 달 추정 사용액, 호출 횟수, 입력·출력 토큰 수, 남은 한도, 최근 사용 내역(어떤 기능에 얼마를 썼는지)을 보여 줍니다. 토큰 수 × 모델 요금으로 계산한 추정치이며, 실제 청구액은 OpenAI 대시보드가 기준입니다.

개인정보·보안: 내 API 키를 쓰면 해석에 필요한 기사 문맥과 수치가 OpenAI로 전송됩니다. 외부로 보내면 안 되는 자료라면 로컬 LLM만 사용을 선택하세요.

중요 사항

데이터 양: 데이터의 양(Period의 수)이 많을 경우, 분석 시간이 길어질 수 있습니다. 이 과정에서 프로그램이 응답하지 않는 것처럼 보일 수 있으나, 이는 정상적인 동작입니다.

제외 단어: 분석에서 제외할 단어들을 지정할 수 있으며, 이들은 필터링된 단어와 함께filtered_words.csv 파일에 기록됩니다. 이는 분석의 정확성을 높이기 위한 과정입니다.

결과 해석: 최종 결과는 키워드의 등장 빈도와 시간에 따른 중요성 변화를 나타냅니다. 이를 통해 특정 키워드가 특정 기간에 급격히 Signal 중요도가 높아졌다면, 해당 기간에 관련된 중요한 사건이 있었음을 추정할 수 있습니다.
