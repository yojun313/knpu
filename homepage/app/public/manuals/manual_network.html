1. 분석 개요

단어 네트워크 분석(Word Network Analysis)은 토큰화된 텍스트 데이터(CSV)에서 단어들이 함께 등장하는 관계(공출현, co-occurrence)를 계산하여, 단어를 노드(node)로, 함께 등장한 관계를 연결선(edge)으로 표현하는 그래프를 생성합니다.

이를 통해 특정 주제 안에서 어떤 단어가 담론의 중심에 있는지, 어떤 단어들이 하나의 의미 덩어리(커뮤니티)를 이루는지, 단어들 사이의 관계 구조가 어떻게 형성되어 있는지를 정량적·시각적으로 파악할 수 있습니다.

본 기능은 상용 네트워크 분석 소프트웨어(NetMiner 등)에서 제공하는 핵심 분석을 자체 파이프라인으로 구현한 것으로, 대용량 데이터를 서버에서 병렬 처리하여 빠르게 연산합니다.

입력 데이터 조건: 이 분석은 토큰화된 CSV(예: token_...csv)를 대상으로 합니다. 각 셀에는 콤마(,)로 구분된 단어 토큰이 들어 있어야 하며, 기간 분할 분석을 사용하려면 Date를 포함하는 날짜 열이 있어야 합니다.

2. 작동 원리

2.1 공출현(Co-occurrence)의 개념

두 단어가 같은 문서(또는 같은 윈도우) 안에서 함께 등장하면, 두 단어 사이에 관계가 있다고 봅니다. 예를 들어 "학교폭력", "예방", "대책"이라는 단어가 여러 기사에서 반복적으로 함께 등장한다면, 이 세 단어는 강하게 연결된 관계로 그려집니다.

함께 등장한 횟수가 많을수록 연결선의 가중치(weight)가 커지고, 네트워크에서 더 굵고 진한 선으로 표현됩니다.

2.2 고속 공출현 행렬 계산

단어 쌍을 하나하나 세는 방식(이중 반복문)은 단어와 문서가 많아지면 매우 느립니다. 본 기능은 이를 희소 행렬(sparse matrix) 연산으로 대체합니다.

  • 문서 × 단어 형태의 이진 행렬 DT를 만든 뒤,
  • 행렬 곱 DTT × DT 한 번으로 모든 단어쌍의 공출현 횟수를 동시에 계산합니다.

이 연산은 내부적으로 멀티스레드(BLAS)로 처리되어, 수십만 건의 문서도 빠르게 집계됩니다. 또한 문서 집합을 CPU 코어 수만큼 나누어 병렬 처리합니다.

2.3 관계의 강도 보정 (연관성 척도)

단순히 "함께 등장한 횟수"만 쓰면, 원래 자주 나오는 흔한 단어끼리 무조건 강하게 연결되는 문제가 있습니다. 이를 보정하기 위해 Jaccard, Cosine, Dice, PMI 등 여러 연관성 척도를 선택할 수 있습니다. (자세한 내용은 6장 참고)

2.4 커뮤니티 탐지와 중심성

생성된 그래프에서 커뮤니티 탐지 알고리즘으로 서로 밀접하게 연결된 단어 그룹을 찾아내고(색으로 구분), 중심성 지표로 각 단어가 네트워크에서 얼마나 중요한 위치에 있는지 수치화합니다.

커뮤니티 개수는 직접 정하는 값이 아닙니다. "3개로 나눠줘" 같은 목표 개수를 입력하는 게 아니라, Louvain/Leiden 알고리즘이 모듈성(modularity)이라는 점수를 최대화하는 방향으로 그래프를 자동으로 쪼갭니다. 모듈성은 "같은 그룹 안의 연결이 무작위로 연결했을 때보다 얼마나 더 촘촘한가"를 재는 지표로, 이 값이 가장 높아지는 지점에서 알고리즘이 멈추기 때문에 결과 커뮤니티 개수는 데이터의 실제 군집 구조에 따라 매번 달라집니다. 즉 단어 네트워크 자체의 연결 밀도와 군집 경향이 개수를 결정하는 것이지, 옵션값이 결정하는 게 아닙니다. 그래서 어떤 데이터는 2~3개로만 뚜렷하게 나뉘고, 어떤 데이터는 10개 넘게 잘게 나뉘기도 합니다.

커뮤니티가 너무 적게(예: 2개) 나뉘어서 뭉뚱그려진다고 느껴지면:

  • 백본 추출(disparity filter)을 켜서 약한 연결을 먼저 걸러낸 뒤 다시 분석해보세요. 노이즈성 연결이 줄어들면 더 세분화된 구조가 드러나는 경우가 많습니다.
  • 엣지 가중치 임계값을 뷰어에서 올려 강한 관계만 남겨보세요 — 전체 재분석 없이도 구조가 어떻게 갈라지는지 눈으로 먼저 가늠해볼 수 있습니다.
  • 연관성 척도를 PMI/NPMI로 바꿔보세요. 흔한 단어 위주로 뭉치는 현상이 줄어들어 더 세밀하게 나뉘는 경우가 있습니다.
  • Louvain 대신 Leiden을 사용해보세요. Leiden은 Louvain의 개선판으로, 내부적으로 연결이 끊긴(disconnected) 커뮤니티가 생기지 않도록 보정하며 결과가 더 안정적입니다.

3. 분석 파이프라인

내부적으로 다음 순서로 처리됩니다.

  1. 단어 사전 구축: 최소 빈도·Top-N 조건에 맞는 단어만 선별
  2. 공출현 행렬 계산: 희소 행렬 곱으로 단어쌍 동시 출현 집계 (병렬)
  3. 연결선 생성: 선택한 연관성 척도로 가중치 계산 + 최소 임계값 필터링
  4. 백본 추출(선택): disparity filter로 핵심 연결만 남김
  5. 중심성 계산: degree, betweenness, pagerank 등
  6. 커뮤니티 탐지: Louvain / Leiden
  7. 전역 지표 계산: 밀도, 평균 경로 길이, 지름, 클러스터링 계수 등
  8. 레이아웃 계산: 노드 좌표 배치 (FR, KK 등)
  9. 결과 출력: PNG, HTML, CSV, GraphML, 요약 파일 생성

기간 분할을 선택한 경우, 각 기간마다 위 과정을 독립적인 프로세스로 동시에 수행하고, 마지막에 기간별 지표 변화를 비교하는 표와 그래프를 추가로 생성합니다.

4. 사용법

  1. 분석 탭에서 네트워크 분석 버튼을 클릭합니다.
  2. 파일 탐색기에서 분석할 토큰화된 CSV를 선택합니다.
  3. 설정 창(단어 네트워크 분석 다이얼로그)에서 원하는 옵션을 지정합니다.
  4. 결과를 저장할 위치를 지정한 뒤 OK를 누릅니다.
  5. 서버에서 분석이 진행되며, 진행 상황이 실시간 메시지로 표시됩니다.
  6. 완료되면 결과 폴더(zip)가 로컬에 저장되는 동시에, 로그인 중인 계정의 온라인 뷰어 프로젝트로도 자동 저장됩니다. "인터랙티브 뷰어로 결과를 확인하시겠습니까?" 다이얼로그에서 예를 누르면 로그인된 상태로 곧바로 웹 브라우저에서 결과를 볼 수 있습니다 (9장).

빠른 시작 권장 설정: 처음이라면 최소 단어 빈도 5, 최소 동시출현 횟수 2, 최대 노드 수 300, 연관성 척도 동시출현 빈도(raw), 커뮤니티 Louvain, 레이아웃 Fruchterman-Reingold로 시작해 보세요.

6. 연관성 척도 설명

두 단어 A, B에 대해, 함께 등장한 횟수를 c, 각각의 등장 횟수를 fA, fB라 할 때 각 척도는 다음과 같이 관계 강도를 계산합니다.

척도특징언제 쓰나
동시출현 빈도 (raw) 단순히 함께 등장한 횟수 c 그대로 사용. 가장 직관적. 절대 빈도가 중요할 때.
Jaccard c / (fA + fB - c). 두 단어가 등장한 전체 대비 함께 등장한 비율. 흔한 단어의 영향을 줄이고 싶을 때.
Cosine c / √(fA × fB). 벡터 코사인 유사도 개념. 빈도 차이가 큰 단어쌍을 공정하게 비교할 때.
Dice 2c / (fA + fB). Jaccard와 유사하나 공통 부분을 더 강조. Jaccard의 대안.
PMI 점별 상호정보량. 우연보다 얼마나 더 자주 함께 나오는지 측정. 흔한 단어를 눌러 의미 있는 조합을 부각할 때.
NPMI 정규화된 PMI. -1~1 범위로 스케일이 안정적. PMI를 쓰되 값의 범위를 일정하게 유지하고 싶을 때.

PMI / NPMI는 우연 대비 관계를 보는 척도라, 음(-)의 연관(서로 잘 안 나오는 쌍)은 연결선에서 제외됩니다.

7. 중심성 지표 설명

지표의미
Degree 직접 연결된 이웃 수. 많을수록 다양한 단어와 함께 쓰이는 단어입니다.
Strength 연결선 가중치의 합. 단순 연결 수가 아니라 관계의 강도까지 반영한 값입니다.
Betweenness 다른 단어들을 잇는 최단 경로 위에 얼마나 자주 놓이는지. 높으면 담론을 매개·연결하는 단어입니다.
Closeness 다른 모든 단어에 얼마나 가깝게 도달하는지. 높으면 네트워크 전반에 빠르게 영향을 미치는 단어입니다.
Eigenvector 중요한 단어와 연결될수록 높아지는 값. "영향력 있는 단어와 연결된 단어"를 찾습니다.
PageRank 구글 검색에 쓰인 알고리즘. eigenvector와 비슷하나 방향/가중치를 안정적으로 반영합니다.
Coreness (k-core) 노드가 속한 최대 k-core. 높을수록 촘촘하게 연결된 핵심부에 속한 단어입니다.
Constraint (구조적 공백) 낮을수록 서로 다른 그룹을 잇는 중개자 역할. 정보 흐름의 길목에 있는 단어입니다.

8. 결과 파일 설명

분석이 완료되면 결과 폴더에 다음 파일들이 생성됩니다.

GraphML이란? 그래프의 노드·연결·속성을 모두 담은 표준 XML 파일입니다. PNG는 고정된 그림이지만, GraphML은 살아있는 데이터라 Gephi(무료) 같은 툴에서 열어 레이아웃을 다시 잡고 색·필터를 자유롭게 바꿀 수 있습니다.

9. 인터랙티브 뷰어 사용법 상세

network.knpu.re.kr은 MANAGER 계정으로 로그인해 쓰는 프로젝트 관리형 뷰어입니다. 네트워크 분석 결과가 로그인한 사용자별 "프로젝트"로 영구 저장되고, 하나의 화면 안에서 프로젝트를 전환하며 볼 수 있습니다(VSCode의 왼쪽 파일 탐색기처럼, 화면을 새로고침하지 않고 즉시 전환됩니다). 예전처럼 viewer.html 파일을 결과 폴더에서 따로 찾아 열 필요가 없습니다. 화면은 크게 ① 왼쪽 프로젝트 레일(프로젝트 목록·업로드·관리), ② 중앙 그래프 캔버스, ③ 상단 검색·상태 바, ④ 좌하단 확대·축소 박스, ⑤ 우측 설정 패널로 구성되어 있습니다.

왜 파일 하나로 주지 않나요? 예전 방식은 노드·엣지 데이터 전체를 하나의 HTML 파일 안에 텍스트로 통째로 박아 넣는 방식이라, 네트워크가 크면 파일 용량이 수십 MB로 커지고 브라우저가 이를 파싱하다가 버벅이거나 먹통이 되는 경우가 있었습니다. 지금은 서버가 데이터를 들고 있다가 필요한 만큼만 내려주고, 커뮤니티 요약·임계값 통계 같은 계산도 서버에서 미리 끝내두기 때문에 훨씬 가볍고 안정적으로 렌더링됩니다.

노드·엣지가 매우 많을 경우, 브라우저 성능 보호를 위해 처음 화면에는 가중치 상위 최대 4,000개 연결선만 표시됩니다(상단 상태 배지에 표시 여부가 나옵니다). 전체 데이터가 필요하면 edges.csv 또는 network.graphml을 이용하세요. 뷰어 자체의 기본 필터값은 모두 0으로 설정되어 있어, 열었을 때 전달받은 노드와 엣지가 모두 표시된 상태로 시작합니다. 프로젝트는 자동으로 삭제되지 않습니다 — 더 이상 필요 없으면 프로젝트 목록에서 직접 삭제하세요.

9.0 로그인 & 프로젝트 만들기

로그인은 MANAGER와 같은 계정을 씁니다(비밀번호 없이 이름 → 이메일 인증코드). 결과를 프로젝트로 가져오는 방법은 세 가지입니다.

  1. MANAGER에서 자동으로(권장): 네트워크 분석이 끝나면 "인터랙티브 뷰어로 결과를 확인하시겠습니까?" 다이얼로그가 뜹니다. 예를 누르면 결과가 이미 여러분 계정의 프로젝트로 저장된 상태로, 로그인까지 자동으로 된 채 웹 브라우저가 열립니다. 별도로 zip을 내려받아 업로드할 필요가 없습니다. 프로젝트 이름은 원본 CSV 파일명을 그대로 씁니다.
  2. 결과 zip 직접 업로드: 왼쪽 레일의 "새 프로젝트 업로드"를 누르면 업로드 창이 뜹니다. 결과 zip 업로드 탭에서 결과 zip 파일을 그대로 드래그하거나 클릭해서 선택하세요(압축을 풀 필요 없습니다).
  3. 웹에서 토큰 CSV로 바로 분석(신규): MANAGER 앱을 켜지 않고도 웹에서 바로 분석을 돌릴 수 있습니다. 업로드 창의 "토큰 CSV로 새로 분석" 탭에서 토큰화된 CSV를 선택하세요. "분석 시작"을 누르면 MANAGER 서버의 분석 파이프라인을 그대로 호출해서 분석하고(데스크톱에서 돌리는 것과 완전히 동일한 백엔드입니다), 끝나면 자동으로 여러분 계정의 프로젝트로 저장됩니다.

업로드 진행률 · 프로젝트 이름

zip이든 토큰 CSV든, 파일을 선택하면 먼저 업로드 진행률 막대가 표시되고, 전송이 100% 끝난 뒤에야 다음 단계가 나타납니다. zip은 업로드가 끝나면 프로젝트 이름을 입력하는 칸이 뜨고(파일명이 기본값으로 채워져 있고 자유롭게 수정할 수 있습니다), "프로젝트 만들기"를 누르면 프로젝트가 생성됩니다. 토큰 CSV는 업로드가 끝난 뒤에야 대상 열·연관성 척도 등 분석 설정 폼(프로젝트 이름 포함)이 나타나며, 큰 파일을 올리는 도중에 미리 설정을 만지다가 꼬이는 일이 없도록 의도적으로 순서를 나눴습니다.

분석 진행 상황 보기

토큰 CSV로 분석을 시작하면(설정 폼 제출 후) 작은 진행 상황 창이 뜹니다. MANAGER 데스크톱 앱에서 분석 중 작은 다이얼로그로 진행 로그가 표시되는 것과 같은 원리로, manager-progress.knpu.re.kr(MANAGER가 실시간 진행 메시지를 주고받는 서버)에 실시간으로 접속해 "단어 사전 구축 중...", "공출현 행렬 계산 중..." 같은 로그를 그대로 보여줍니다. 완료되면 자동으로 진행 창이 닫히고 해당 프로젝트로 바로 이동합니다. 실패하면 오류 메시지가 로그에 표시되고 창을 닫을 수 있습니다.

기간 분할 분석으로 여러 네트워크가 들어있는 zip을 올리면, 프로젝트를 열었을 때(또는 프로젝트 목록에서) 어느 기간을 볼지 선택할 수 있고, 뷰어 화면 상단의 네트워크 선택 메뉴로 나중에 바꿀 수도 있습니다. 왼쪽 레일에서 항목에 마우스를 올리면 나타나는 이름 변경(✎)·삭제(🗑) 버튼으로 프로젝트를 관리하세요. 레일은 오른쪽 가장자리를 드래그해 너비를 조절하거나, 상단의 ☰ 버튼으로 완전히 접을 수 있습니다(너비·접힘 상태는 브라우저에 기억됩니다). 좌측 패널 위쪽의 📘 버튼을 누르면 이 매뉴얼(knpu.re.kr/manual/network)이 새 탭으로 열립니다.

9.3 분석 설정 패널

이 결과는 어떤 설정으로 만들어졌나

MANAGER(데스크톱 또는 웹)로 분석한 프로젝트를 열면, 우측 패널 가장 위쪽에 "분석 설정" 항목이 나타납니다. 분석을 실행한 시각, 원본 파일명, 그리고 대상 열·연관성 척도·기간 분할·최소 빈도·최소 동시출현·Top-N·커뮤니티 알고리즘·레이아웃·백본 추출 여부· 계산한 중심성 목록까지 분석 시 사용한 옵션이 모두 표시됩니다. 결과 zip 안의 analysis_options.json 파일에서 읽어오는 값으로, 나중에 "이 그래프를 어떤 조건으로 만들었더라?"를 다시 분석 창을 열어보지 않고도 바로 확인할 수 있습니다.

오래전 결과이거나 다른 방식으로 만들어진 zip(이 파일이 없는 경우)을 업로드했다면 이 패널 자체가 표시되지 않습니다.

9.4 좌측 노드 정보 패널

노드 정보

노드를 클릭하면 단어 이름, 소속 커뮤니티 번호, 빈도, 그리고 분석 시 계산해 둔 모든 중심성 지표 (연결 정도, 강도, 매개 중심성, 근접 중심성, 고유벡터, PageRank, k-core, 구조적 공백 등)가 나열됩니다. 필터에 의해 현재 숨겨진 노드는 검색해도 "숨겨진 노드입니다" 안내가 표시됩니다. 노드를 클릭·검색해도 노드 자체의 크기는 바뀌지 않으므로, 다른 메뉴에서 크기를 다시 맞출 필요 없이 계속 같은 화면 비율로 비교하며 볼 수 있습니다.

9.5 필터 패널

엣지 가중치 ≥ 기본값 0

이 값보다 작은 가중치를 가진 연결선을 화면에서 숨깁니다. 슬라이더를 오른쪽으로 옮길수록 약한 관계가 사라지고 강한 관계(굵은 선)만 남아 핵심 구조가 뚜렷해집니다. 슬라이더 옆 숫자 입력칸에 값을 직접 타이핑해서 정확한 임계값을 지정할 수도 있습니다. 슬라이더 아래에는 현재 데이터의 중앙값·상위 25%·상위 10% 가중치가 안내 문구로 함께 표시되므로, "일단 상위 25% 지점부터 잘라보고 그래프를 보면서 조절"하는 식으로 값을 잡는 데 참고하세요. 가중치가 정확히 어떻게 계산됐는지는 6장 연관성 척도를 참고하세요.

노드 최소 빈도 ≥ 기본값 0

이 값보다 적게 등장한 단어(노드)를 화면에서 숨깁니다. 값을 높이면 자주 등장한 핵심 단어 위주로 그래프가 단순해집니다. 엣지 가중치와 마찬가지로 숫자 입력칸으로 직접 값을 넣을 수 있고, 아래에 중앙값·상위 25%·상위 10% 빈도가 참고용으로 표시됩니다.

연결 없는(고립) 노드 숨기기 기본값 꺼짐

현재 필터 조건에서 연결선이 하나도 없는 노드를 화면에서 제외합니다. 전체 그래프를 깔끔하게 보고 싶을 때 켜면 좋습니다.

9.6 노드 모양 · 크기 패널

모양 기본값 dot

노드를 그릴 도형을 선택합니다. dot(원, 값에 비례해 크기 변화), circle(라벨 길이에 맞춰 자동 크기 조정되는 원), ellipse, box, diamond, star, triangle, square 중 선택할 수 있습니다.

크기 기준 기본값 빈도(freq)

노드 크기를 어떤 지표에 비례시킬지 선택합니다. 빈도 외에도 분석 시 계산된 모든 중심성 지표(연결 정도, 매개 중심성, PageRank 등)를 기준으로 삼을 수 있습니다. 예를 들어 "매개 중심성"을 기준으로 하면, 담론을 연결하는 허브 단어가 크게 표시됩니다.

크기 범위(min/max) 기본값 6 / 55

노드가 그려질 수 있는 최소·최대 픽셀 크기입니다. 노드가 너무 작아 안 보이거나, 큰 노드가 화면을 가릴 때 조정하세요.

테두리 두께 / 테두리 색 기본값 1.5px / 흰색

노드 원(도형) 바깥 테두리의 두께와 색상입니다. 배경과 대비되는 색을 주면 노드 경계가 또렷해집니다.

9.7 노드 색상 패널

색상 기준 기본값 커뮤니티별 팔레트

커뮤니티별 팔레트: Louvain/Leiden으로 탐지된 그룹마다 고유 색을 자동 배정합니다.
단일 색상: 모든 노드를 같은 색으로 표시합니다(구조보다 형태에 집중하고 싶을 때).
지표 기반 그라디언트: 선택한 중심성 지표 값이 낮을수록 "낮은 값" 색, 높을수록 "높은 값" 색으로 서서히 변하는 히트맵 형태로 표시합니다. 어떤 단어가 특정 지표에서 두드러지는지 한눈에 볼 수 있습니다.

9.8 라벨 패널

라벨 표시 기본값 켜짐

노드 위에 단어 텍스트를 표시할지 여부입니다. 노드 수가 매우 많아 텍스트가 겹쳐 보일 때는 꺼서 구조만 먼저 파악한 뒤, 관심 있는 부분만 확대해서 다시 켜는 방식을 추천합니다.

글자 크기 / 글자 색 기본값 14px / #2c3e50

라벨 텍스트의 크기와 색상입니다. 배경 테마(밝게/어둡게)에 따라 자동으로 대비가 맞춰지지만, 직접 원하는 색으로 바꿀 수도 있습니다.

9.9 엣지(연결선) 패널

색상 / 불투명도 기본값 회색조 / 0.55

연결선의 색상과 투명도입니다. 노드가 많아 선이 복잡할 때 불투명도를 낮추면 배경처럼 은은해지고, 높이면 관계가 더 선명하게 강조됩니다.

두께 범위(min/max) 기본값 0.5 / 6

가중치가 가장 낮은 엣지와 가장 높은 엣지가 각각 몇 픽셀 두께로 그려질지의 범위입니다. 두 값의 차이를 크게 벌릴수록 강한 관계와 약한 관계의 대비가 뚜렷해집니다.

곡선(curve) 엣지 기본값 꺼짐

직선 대신 완만한 곡선으로 연결선을 그립니다. 노드 사이에 여러 겹의 선이 겹칠 때 구분이 쉬워지지만, 노드 수가 매우 많으면 렌더링이 다소 느려질 수 있습니다.

화살표 표시 기본값 꺼짐

연결선 끝에 화살표를 그려 방향성을 표시합니다. 단어 네트워크는 기본적으로 방향이 없는 관계이므로 꺼두는 것이 일반적입니다.

물리 엔진(힘 기반 재배치) 기능은 제공하지 않습니다. 켤 때마다 배치가 계속 흔들리거나, 매번 다른 모양으로 튀는 등 결과가 일관되지 않다는 피드백에 따라 제거했습니다. 대신 분석 시 서버에서 계산해 둔 배치(Fruchterman-Reingold 등, 5.3 시각화 옵션에서 선택한 레이아웃)를 항상 고정된 좌표로 그대로 보여주므로, 같은 결과 zip을 다시 열어도 매번 동일한 모양으로 표시됩니다.

9.10 보기·조작 패널

휠로 확대/축소 기본값 켜짐

마우스 휠로 화면을 확대·축소할 수 있는지 여부입니다. 발표 화면 등에서 실수로 확대되는 것을 막고 싶을 때 꺼두세요.

노드 드래그 허용 기본값 켜짐

마우스로 노드를 직접 옮길 수 있는지 여부입니다. 레이아웃을 고정해서 보여줄 때는 꺼두면 실수로 위치가 흐트러지지 않습니다.

전체 보기 버튼 / 배경(중심)·배경(외곽)

전체 보기 버튼은 모든 노드가 화면 안에 들어오도록 자동으로 맞춥니다. 배경 색상 두 개는 캔버스 중심에서 바깥쪽으로 퍼지는 그라디언트 배경의 색을 지정합니다.

9.11 커뮤니티 패널

커뮤니티 범례

탐지된 각 커뮤니티의 색상과 소속 노드 수를 보여줍니다. 항목을 클릭하면 해당 커뮤니티에 속한 노드만 선택되어 화면이 그 그룹으로 확대·이동합니다. 특정 주제 군집만 따로 살펴볼 때 유용합니다.

커뮤니티별 대표 단어

각 커뮤니티 항목 아래에 서버가 미리 계산해 둔 대표 단어 두 줄이 함께 표시됩니다.

  • 핵심어(빈도): 그 커뮤니티 안에서 가장 자주 등장한 단어. 그룹의 주제를 가장 직관적으로 보여줍니다.
  • 응집 허브어(내부연결): 같은 커뮤니티 안의 다른 단어들과 가장 많이 연결된 단어. 그 그룹을 구조적으로 묶어주는 단어입니다.

시각화만으로는 커뮤니티끼리 무엇이 다른지 알아보기 어렵다는 피드백을 반영한 기능으로, 색으로 나뉜 군집이 실제로 어떤 주제인지, 다른 군집과 무엇이 다른지를 그래프를 헤집지 않고도 바로 확인할 수 있습니다.

9.12 내보내기 · 초기화 패널

PNG로 저장

현재 화면에 보이는 그래프를 그대로 PNG 이미지 파일로 다운로드합니다. 보고서나 발표 자료에 캡처본을 바로 삽입할 때 편리합니다(단, 현재 확대/이동 상태 그대로 저장됩니다).

모든 설정 초기화

모양·크기·색상·라벨·엣지·필터 등 지금까지 바꾼 모든 옵션을 처음 뷰어를 열었을 때의 기본값으로 되돌리고, 화면을 전체 보기로 맞춥니다.

9.13 우측 상단 테마 전환 버튼

◐ 화면 테마 전환

그래프 캔버스뿐 아니라 왼쪽 프로젝트 레일과 우측 설정 패널을 포함한 화면 전체가 밝은 테마/어두운 테마로 함께 전환됩니다. 라벨 색, 테두리 색, 엣지 색, 커뮤니티 색상 팔레트도 테마에 맞게 자동으로 조정됩니다. 라이트 모드는 MANAGER 데스크톱 앱의 라이트 테마와 같은 배색(흰 배경, 네이비 강조색)을 씁니다. 발표 환경(밝은 회의실 vs 어두운 스크린)에 맞춰 전환해 사용하세요.

10. 활용 팁 & 주의사항

  • 그래프가 너무 복잡하면 최소 빈도·최소 동시출현 횟수를 높이거나 Top-N을 줄여 단순화하세요.
  • 흔한 단어(예: "때", "말", "일")가 과도하게 중심에 오면 토큰화 단계에서 예외어로 제거하거나 PMI/NPMI 척도를 사용하세요.
  • 라벨이 노드에서 벗어나 보이면 라벨 겹침 방지를 끄고, 라벨 표시 개수를 20~25개로 줄이세요.
  • 커뮤니티가 잘 나뉘지 않으면 백본 추출을 켜서 핵심 연결만 남긴 뒤 다시 분석해 보세요.
  • 시간에 따른 담론 변화를 보려면 기간 분할을 사용해 period_comparison 결과를 확인하세요.
  • Top-N을 크게(수천 이상) 잡으면 betweenness 계산이 느려질 수 있습니다. 필요 없으면 중심성 선택에서 제외하세요.
  • 뷰어를 처음 열었을 때 그래프가 비어 보인다면, 우측 "필터" 패널의 슬라이더 값이 모두 0인지 확인하세요. 0이면 전달된 노드·엣지가 모두 표시되는 상태입니다.
  • 뷰어에서 바꾼 색상·크기·필터 설정은 저장되지 않습니다. 마음에 드는 스타일을 찾았다면 PNG로 저장해 두거나, 결과 zip을 보관해두었다가 나중에 다시 업로드하세요.

엣지 가중치 임계값, 이렇게 잡아보세요. "얼마로 설정해야 할지 모르겠다"는 질문이 가장 많습니다. 정답은 없지만 다음 순서를 권장합니다.

  1. 0에서 시작해 전체 구조를 한 번 훑어봅니다(보통 선이 너무 많아 뒤엉켜 보입니다).
  2. 필터 패널에 안내되는 상위 25%(p75) 지점으로 값을 올려, 상단 배지의 "표시 중 N개 엣지" 숫자가 수백 개 수준으로 줄어드는지 확인합니다.
  3. 여전히 복잡하면 상위 10%(p90)까지 올려 정말 강한 관계만 남깁니다.
  4. 너무 많이 잘려서 그래프가 조각나면(연결요소 수가 급격히 늘면) 한 단계 낮춰 되돌립니다.

노드 최소 빈도도 같은 방식으로, 중앙값(p50)부터 시작해 올려보는 것을 권장합니다. 가중치 자체가 어떻게 계산되는지는 6장을 참고하세요.
